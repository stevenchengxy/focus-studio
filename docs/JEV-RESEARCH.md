# Jev 在 Focus Studio 中的适用边界

调研日期：2026-09-22。这里的 Jev 指 TypeSafe 的 System One 模型，不是同名第三方聊天网站。下列产品建议是我们的判断，不代表已接入 Jev，也不是性能承诺。

## 已核实的运行逻辑

- 输入是当前状态 `state` 和若干有明确候选项的问题，输出是 Choice、Score 或 Noul，而不是聊天回复。问题可在同一请求内独立求值；依赖前一个结果的问题仍需要下一轮。[官方概览](https://docs.typesafe.ai/introduction)、[问题类型](https://docs.typesafe.ai/primitives)
- Choice / Score 的 confidence 与候选项概率分布有关；不等于动作授权或正确性证明。低把握时应补充观察或交给人确认，阈值必须根据实际场景验证。[置信度说明](https://docs.typesafe.ai/confidence)
- Browser Use 的开源示例每次先生成当前页面控件表，选择兼容的动作和目标，再由程序重新核验目标、解析实时位置并执行。它另用语言模型生成输入文字，且 DONE 不代替独立验收。其短演示速度不能推广成普遍成功率。[源码与限制](https://github.com/browser-use/jev-ultrafast)

## 我们应如何借鉴

| 场景 | 建议使用方式 | 边界 |
| --- | --- | --- |
| 助手聊天 | Codex / 已配置语言模型负责对话、解释和计划 | Jev 不替代聊天大模型 |
| 自动录制网页 | 观察控件 → 从候选动作中选择 → 校验新鲜度 → 执行 → 验证 | 不直接执行模型生成的脚本；不将历史坐标当作仍有效 |
| 点击、输入缩放 | 本地输入事件和时间线算法负责聚焦、保持、交接、缓动 | 不逐帧请求云模型，避免网络抖动和输入隐私外传 |
| 录后剪辑建议 | 对本地生成的候选片段评分，建议重点镜头、冗余停顿和章节 | 先呈现建议，不自动覆盖手动编辑 |
| 执行安全 | 有限工具类型、明确确认、取消、结果回读 | 高置信度不能绕过录屏或付费操作的确认 |

推荐结构：语言模型负责理解和创作，独立的有限候选决策模块负责快速判断，原生执行器负责权限、目标核验、录制和编辑。录屏渲染始终本地执行。

## 本轮采用 / 暂不采用

本轮采用：共享聊天与录制计划预览；录制前显式确认；失败重试避免重复执行已完成工具；点击与输入焦点按事件顺序交接；本地缩放算法和确定性回归测试。它们是借鉴上述边界后的本地工程改进，不是 Jev 推理。

暂不直接接入：Jev 云 API、常驻屏幕观察、语音半句即执行、自动删除/发布/支付、模型自行声明完成后自动停止验收。用户请求是调研和参考，未因此新增云数据接收方或上传录屏。

若之后接入 Jev，先由用户显式配置 TypeSafe 或已选网关的凭据与数据范围；只发送最少的已脱敏状态，不发送密码、原始按键、整段录屏。先在固定测试集比较任务成功率、错误动作数、端到端耗时和成本，再决定是否启用。保留无 Jev 时的现有功能路径。当前没有 Jev 在线调用或真实账号端到端验证。

## Codex 多轮对话依据

现有 Swift 原生集成使用 Codex app-server，可通过 thread/start、thread/resume、turn/start 管理连续会话，无须为了聊天再引入一个 Node 服务。[OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)、[Codex SDK 多轮说明](https://learn.chatgpt.com/docs/codex-sdk)
