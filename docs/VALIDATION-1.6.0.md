## 行为与边界

- “显示鼠标指针”在录制设置和录后“鼠标”面板均可修改，不影响自动缩放和点击动画。不能抹掉外部导入视频/截图里已经烧录的指针。
- 工具栏覆盖屏幕、窗口、区域来源；准备阶段必须点击“开始录制”，倒计时可取消。录中可以截图、暂停、继续、停止；暂停状态也可直接结束。
- 源图像和音频在暂停时停止写入；继续时重新验证同一来源，等到首帧才恢复计时。窗口移动后的坐标重新映射；缺失来源不会静默切换。
- 暂停/继续/停止串行执行；浮动栏点击不生成录屏缩放。录制失败会保留仅本次会话的恢复文件，不删除用户项目。
- 录前截图也使用网页裁剪，并原子保存原始分辨率 PNG。
- 只准备 Universal（arm64 + x86_64）本地包。Intel 实机、第二块物理显示器、系统音频/麦克风真实硬件切换未在本机覆盖。签名与公证限制见安装文档。

## 原生界面、更新安装

build 11 已通过以下本机检查：

1. 准备页面停留不自动录制；点击开始后显示 3 秒倒计时。
2. 使用独立 Chrome 本地 fixture 窗口。暂停后 `0:47` 保持不变，之后点击继续，计时重新增长；再次暂停至 `1:13`，点击结束后成功进入编辑器。
3. 项目 `EFA889E2-035F-4EE3-BBF3-3E6D440A4FFC` 保存为 `QA 1.6 — Pause resume and stop`。实际 H.264 文件 2992×1866、72.845 秒；4093 个解码帧的展示时间全部严格递增（0 至 72.833333 秒）。`ffmpeg -fps_mode passthrough -enc_time_base 1/60000 -f null -` 全片解码退出 0、无错误。原始 packet 的一个倒序点含 edit-list 丢弃标志，不是解码展示帧倒序；默认 null muxer 的低精度时间基会产生舍入警告，不能据此判断源损坏。
4. 录中截图成功。录前关闭指针后，项目 JSON `settings.showCursor=false`，编辑器指针开关仍关闭，但点击动画选项仍开启、可编辑。未自动添加音乐。
5. 新控制台使用真实 SwiftUI `NSHostingView` 离屏渲染 760×116 / 640×116 快照，实际原生 Menu 标签可见、无裁切；测试窗口从未显示。图片位于 `.artifacts/qa-1.6.0-b11/toolbar-ready.png` 与 `toolbar-ready-640.png`。没有把离屏快照称为实际多屏点击验收。
