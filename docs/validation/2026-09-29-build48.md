# Build 48 post-click validation (2026-09-29)

Build 48 is an ad-hoc signed, arm64 local development installation of Focus Studio 1.12.0. Its change is limited to the in-app AI assistant's interactive Codex recording path: after a successful Codex click, an attempted stop or final reply yields additional live page frames at least 2, 5 and 10 seconds after the click, on separate model turns. The model can continue observing when the destination is still loading. The existing recording duration watchdog still bounds the task, and the manual mouse recording algorithm was not changed.

The defect was observed in installed build 47: its in-app assistant clicked a Finlyze navigation item and saved at 15.7 seconds, but an independently inspected frame at 15.5 seconds still showed a loading spinner. That take was a valid interaction recording but did not contain a usable destination shot. See [the build 47 checkpoint](2026-09-29-build47.md) for the full external MCP record/edit/export validation and source project IDs.

- `zsh scripts/test-ai-assistant.sh --skip-build` passed with focused scripted checks for premature model replies, three distinct later frame observations, an unavailable window, and the duration limit interrupting a pending observation. `swift build --product FocusStudio` and `git diff --check` passed.
- `FOCUS_STUDIO_ARCHS=arm64 zsh scripts/build-app.sh --install` built, signed, verified and installed build 48 at `/Applications/Focus Studio.app`. Packaging checked both localizations, the 46-tool MCP catalog and bundled assets. The external `get_status` MCP call to the installed app reported build 48 and granted Screen Recording, Accessibility and Input Monitoring permissions.
- `zsh scripts/test-app-regression.sh --skip-build` passed on build 48 sources. This covers editor playback and editing, manual and Codex interaction paths, the automation bridge, connector and MCP helper end-to-end fixtures. It does not replace a physical hand-operated mouse test of this build; that algorithm was not edited.
- In the installed app, the AI assistant was asked for a silent, maximum-45-second, one-click demo of an existing Chrome product dashboard. It presented the exact-window task review, observed the source, clicked once through Codex computer use, continued to inspect the destination and saved a 28.465-second project, `A4CC8341-1DB6-4EF3-9F8D-ABFD0BB60A44`. The external read-only `get_project` response independently reported one click, 23 cursor samples from the `execution` source, zero rejected events and one automatic zoom from 7.2 to 8.7 seconds. The assistant used a live `capture_frame` around 27 seconds. An independent frame at 27 seconds showed the destination's populated search box and eight asset cards without a spinner.
- No microphone, paid video model, site-data change or export was requested in the build 48 in-app take. Model-based page recognition is still a visual judgment, so a generic workflow cannot guarantee that every website has fully loaded. The recorded Chrome window included a browser-debug banner; this take tests recording behavior rather than serving as a finished marketing video. The separate external Codex MCP export from build 47 remains `.artifacts/finlyze-mcp-build47/Finlyze-Codex-MCP-Demo-26s.mp4` and passed full FFmpeg decode.

The new-user [Codex connection guide](../CODEX-SETUP.md) explains first-call approval and the difference between the in-app assistant's Codex account and an external MCP client. The [AI model guide](../AI-MODEL-SETUP.md) covers separate Ark and Gemini credentials; no real paid Seedance or Veo generation is claimed here.

A subsequent code review found that an over-limit action or unexpected planning object could bypass build 48's post-click check. The follow-up guard and tests are tracked in [build 49](2026-09-29-build49.md) and [issue #22](https://github.com/stevenchengxy/focus-studio/issues/22).
